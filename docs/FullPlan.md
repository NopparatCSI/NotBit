# แผนรวมเว็บไซต์ Game Item Marketplace บน Sepolia พร้อมระบบ Admin และ Super Admin

## 1. เป้าหมายและขอบเขตโครงการ

พัฒนาเว็บไซต์ตลาดกลางสำหรับลงขายไอเทมเกม ผู้ซื้อและผู้ขายพูดคุย ตกลงราคา นัดส่งมอบ และแนบหลักฐานผ่านแพลตฟอร์ม โดยใช้ **Smart Contract แบบ Escrow พักเงินของผู้ซื้อก่อนส่งสินค้า**

เมื่อผู้ขายยืนยันส่งและผู้ซื้อยืนยันรับ ระบบจ่ายเงินให้ผู้ขาย **95%** และแพลตฟอร์ม **5%** หากมีข้อพิพาทหรือหมดเวลาดำเนินการ เงินจะพักไว้จนกว่าผู้ดูแลจะตัดสิน

เวอร์ชันแรกเป็นโปรเจกต์สาธิต มีขอบเขตดังนี้:

- ใช้ **Sepolia ETH** ไม่รับเงินจริง และจำลองการส่งไอเทมในเกม
- เว็บไซต์ภาษาไทย ธีมเข้ม รองรับคอมพิวเตอร์และมือถือ
- แสดงแถบ “ระบบทดสอบ Sepolia — ไม่ใช้เงินจริง” ทุกหน้าที่เกี่ยวข้อง
- ลงชื่อเข้าใช้ด้วย MetaMask โดยหนึ่ง Wallet เป็นหนึ่งบัญชี
- ผู้ใช้ทั่วไปสลับหน้าผู้ซื้อและผู้ขายได้
- แยกบัญชีผู้ดูแลออกจากบัญชีซื้อขาย มีระดับ **Admin** และ **Super Admin**
- หนึ่งออเดอร์มีผู้ซื้อหนึ่งราย ผู้ขายหนึ่งราย และสินค้าเป็นหนึ่งไอเทมหรือหนึ่งชุด
- ข้อพิพาทตัดสินได้สองแบบ: คืนเงินเต็มจำนวน หรือจ่ายตามดีลโดยหักค่าบริการ

### เกมตัวอย่างสำหรับข้อมูลสาธิต

| เกม | ตัวอย่างสินค้า |
|---|---|
| Counter-Strike 2 | สกินอาวุธและไอเทมที่แลกได้ |
| Team Fortress 2 | หมวก อาวุธ และไอเทมที่แลกได้ |
| Warframe | Mods และชิ้นส่วน Prime ที่แลกได้ |

ใช้ชื่อเกมและรายการสินค้าเพื่อจำลองขั้นตอนเท่านั้น ยังไม่เชื่อม inventory หรือระบบแลกของจริง การเปิดบริการจริงต้องตรวจเงื่อนไขรายเกม โดยเฉพาะข้อจำกัดการซื้อขายภายนอกเกมและการย้อนคืนการแลกสินค้า

**ข้อจำกัดของระบบ:** Smart Contract ยืนยันเงินฝากและบังคับกติกาจ่ายเงินได้ แต่ตรวจเองไม่ได้ว่าส่งไอเทมในเกมจริงหรือไม่ การตัดสินข้อพิพาทจึงยังอาศัยหลักฐานและความน่าเชื่อถือของผู้ดูแล

## 2. บทบาท หน้าจอ และการจัดการผู้ใช้

### สิทธิ์ของแต่ละบทบาท

| ความสามารถ | ผู้ใช้ทั่วไป | Admin | Super Admin |
|---|:---:|:---:|:---:|
| ซื้อ ขาย แชท และจัดการออเดอร์ของตนเอง | ✓ | — | — |
| จัดการข้อมูลผู้ใช้ทั่วไป | — | ✓ | ✓ |
| ระงับ/คืนสถานะผู้ใช้และประกาศ | — | ✓ | ✓ |
| ตรวจหลักฐานและตัดสินข้อพิพาท | — | ✓ | ✓ |
| เพิ่ม แก้ไข และถอดสิทธิ์ Admin | — | — | ✓ |
| แต่งตั้งและถอดสิทธิ์ Super Admin | — | — | ✓ |
| ดูประวัติการเปลี่ยนสิทธิ์ทั้งหมด | — | — | ✓ |
| หยุดรับเงินฝากใหม่เมื่อเกิดเหตุฉุกเฉิน | — | — | ✓ |

การตรวจสิทธิ์ต้องทำทั้งหน้าเว็บ API ฐานข้อมูล พื้นที่เก็บไฟล์ และ Smart Contract ไม่ใช้เพียงการซ่อนเมนู

### หน้าตลาดกลางและหน้าผู้ใช้

| หน้า | ฟีเจอร์หลัก |
|---|---|
| ตลาดกลาง | ค้นหาสินค้า กรองเกม ประเภท ราคา และเรียงรายการล่าสุด |
| รายละเอียดสินค้า | รูป รายละเอียด จำนวน เกม เซิร์ฟเวอร์/ภูมิภาค วิธีส่งมอบ ราคา โปรไฟล์ผู้ขาย และปุ่มแชท |
| หน้าผู้ซื้อ | ออเดอร์รอฝากเงิน รอรับสินค้า ข้อพิพาท และประวัติการซื้อ |
| หน้าผู้ขาย | เพิ่ม แก้ไข พักประกาศ ออเดอร์รอส่ง ยอดขาย ค่าบริการ และรายได้สุทธิ |
| หน้าบัญชี | Wallet ชื่อแสดงผล บัญชีตัวละครที่กรอกเอง และรีวิว |
| การแจ้งเตือน | ข้อความใหม่ เงินฝากสำเร็จ การยืนยัน กำหนดเวลา และผลข้อพิพาท |

บัญชีเกมที่ผู้ใช้กรอกเองต้องแสดงว่า **ยังไม่ได้ยืนยันกับเจ้าของเกม** และรีวิวได้เฉพาะผู้ซื้อของออเดอร์สำเร็จ หนึ่งรีวิวต่อออเดอร์

### ห้องซื้อขาย

หน้าห้องซื้อขายประกอบด้วยสามส่วน:

1. **สรุปดีล:** สินค้า คู่ค้า บัญชีตัวละคร ราคา ค่าบริการ นัดหมาย และเวลาที่เหลือ
2. **แชทและหลักฐาน:** แชทเจรจา รูปประกอบ และช่องหลักฐานส่ง/รับที่แยกกัน
3. **สถานะและการดำเนินการ:** ฝากเงิน ยืนยันส่ง ยืนยันรับ เปิดข้อพิพาท และดูธุรกรรม

บนมือถือแสดงเป็นแท็บ สรุปดีล / แชท / หลักฐาน ผู้ใช้เริ่มคุยจากประกาศได้ก่อนซื้อ และแชทก่อนซื้อจะเชื่อมกับออเดอร์เมื่อเกิดข้อตกลง

### หน้า Admin

แบ่งเมนูเป็น:

- ภาพรวมออเดอร์และงานค้าง
- จัดการผู้ใช้ทั่วไป
- จัดการประกาศและรายงาน
- คิวข้อพิพาทและออเดอร์เกินกำหนด
- ประวัติการตรวจสอบและคำตัดสิน

หน้า **จัดการผู้ใช้ทั่วไป** รองรับค้นหาด้วยชื่อ Wallet หรือรหัสผู้ใช้ ดูประวัติซื้อขาย แก้ชื่อแสดงผลหรือซ่อนข้อมูลไม่เหมาะสม ระงับ คืนสถานะ และปิดบัญชี โดยต้องระบุเหตุผล

การระงับบัญชีห้ามสร้างดีลใหม่ แต่ยังให้ผู้ใช้เข้าถึงออเดอร์เดิม ส่งหลักฐาน เปิดข้อพิพาท และรับเงินตามสิทธิ์ ผู้ดูแลเปลี่ยน Wallet แก้ยอดเงิน หรือแก้ประวัติธุรกรรมไม่ได้

### หน้า Super Admin

มีความสามารถทั้งหมดของ Admin และเพิ่มหน้า **จัดการผู้ดูแลระบบ**:

- แสดงชื่อ Wallet บทบาท สถานะ ผู้แต่งตั้ง วันที่แต่งตั้ง และสถานะสิทธิ์บน Contract
- เพิ่มผู้ดูแลจากบัญชีที่ยืนยันการครอบครอง Wallet แล้วและไม่ได้ใช้ซื้อขาย
- แก้ชื่อแสดงผล หมายเหตุ และเปลี่ยนบทบาท Admin ↔ Super Admin
- ถอดสิทธิ์และปิดสถานะผู้ดูแล โดยไม่ลบประวัติเดิม
- ดูประวัติการเปลี่ยนสิทธิ์และสถานะธุรกรรมที่ยังดำเนินการไม่ครบ

กติกาการจัดการผู้ดูแล:

- Super Admin คนแรกกำหนดตอนติดตั้งระบบ ไม่มีหน้าสมัครสาธารณะ
- การแต่งตั้ง Super Admin ใหม่ต้องให้ผู้รับยอมรับผ่าน Wallet
- ต้องเหลือ Super Admin ที่ใช้งานได้อย่างน้อยหนึ่งบัญชีเสมอ รวมถึงกรณีลาออกจากสิทธิ์บน Contract โดยตรง
- Admin เปลี่ยนสิทธิ์ตนเองหรือจัดการ Super Admin ไม่ได้
- การเปลี่ยน Wallet ใช้วิธีเพิ่มบัญชีใหม่และถอนสิทธิ์บัญชีเดิม
- การ “ลบ” ผู้ใช้หรือผู้ดูแลหมายถึงปิดสถานะ ไม่ลบแชท หลักฐาน ออเดอร์ หรือคำตัดสินย้อนหลัง

## 3. ขั้นตอนซื้อขาย การพักเงิน และระบบหลักฐาน

### เส้นทางซื้อขายปกติ

**เลือกสินค้า → แชทตกลง → ผู้ขายส่งข้อเสนอ → ผู้ซื้อฝากเงิน → ผู้ขายยืนยันส่ง → ผู้ซื้อยืนยันรับ → จ่ายเงิน**

| ขั้นตอน | พฤติกรรมระบบ |
|---|---|
| ตกลงดีล | บันทึกสินค้า ราคา คู่ค้า วิธีส่งมอบ และนัดหมายเป็นข้อตกลงฉบับเฉพาะออเดอร์ |
| รอฝากเงิน | ข้อเสนอมีอายุ 30 นาที หมดอายุแล้วต้องสร้างข้อเสนอใหม่ |
| ส่งธุรกรรมฝาก | แสดง “กำลังตรวจสอบเงินฝาก” ยังไม่ถือว่าเงินเข้า |
| ฝากสำเร็จ | ตรวจ Contract และรออย่างน้อย 3 confirmations ก่อนแจ้งผู้ขายว่าเงินอยู่ในระบบ |
| ยืนยันส่ง | ผู้ขายแนบหลักฐานอย่างน้อยหนึ่งภาพและยืนยันผ่าน Wallet |
| ยืนยันรับ | ผู้ซื้อแนบหลักฐานอย่างน้อยหนึ่งภาพและยืนยันผ่าน Wallet หลังผู้ขายยืนยันส่ง |
| จ่ายเงิน | ผู้ขายได้รับ 95% แพลตฟอร์มได้รับ 5% |

หลังฝากเงินแล้ว ข้อตกลงของออเดอร์แก้ไขไม่ได้ การแก้ประกาศในภายหลังต้องไม่เปลี่ยนข้อมูลออเดอร์เดิม

ก่อนผู้ซื้อยืนยันรับ ต้องแสดงว่าการยืนยันจะปล่อยเงิน และหลังจ่ายสำเร็จไม่สามารถใช้ข้อพิพาทในสัญญานี้ดึงเงินกลับได้

ตัวอย่างราคาสินค้า **0.01 Sepolia ETH**:

| รายการ | จำนวน |
|---|---:|
| ผู้ซื้อฝาก | 0.01 ETH |
| ผู้ขายได้รับ | 0.0095 ETH |
| แพลตฟอร์มได้รับ | 0.0005 ETH |

ค่า Gas แยกจากราคาสินค้า ผู้ส่งธุรกรรมแต่ละครั้งเป็นผู้จ่าย กรณีคืนเต็มจำนวนจะคืนเงินต้น แต่ไม่คืนค่า Gas ที่ใช้ไปแล้ว

### กำหนดเวลาและข้อพิพาท

| เหตุการณ์ | ผลลัพธ์ |
|---|---|
| ไม่ฝากเงินภายในอายุข้อเสนอ | ข้อเสนอหมดอายุ ไม่มีเงินให้คืน |
| ฝากแล้วไม่ยืนยันส่งภายใน 24 ชั่วโมง | รอ Admin ตรวจ และพักเงินต่อ |
| ยืนยันส่งแล้วไม่ยืนยันรับภายใน 48 ชั่วโมง | รอ Admin ตรวจ และพักเงินต่อ |
| คู่ค้าเปิดข้อพิพาทก่อนจ่าย | เมื่อธุรกรรมเปิดข้อพิพาทสำเร็จ ให้หยุดเส้นทางจ่ายเงินปกติ |
| ต้องการยกเลิกหลังฝาก | ส่งคำขอให้ Admin ตรวจและตัดสินคืนเงิน |
| ผู้ดูแลยังไม่ตัดสิน | เงินยังพักอยู่ พร้อมแสดงระยะเวลารอ |

Contract ต้องปฏิเสธการยืนยันตามเส้นทางปกติเมื่อพ้นกำหนด แม้งานเบื้องหลังยังไม่ได้เปลี่ยนสถานะบนหน้าเว็บ

**การเงียบหรือหมดเวลาไม่ใช่หลักฐานว่าส่งหรือรับสินค้าแล้ว** จึงไม่มีการปล่อยเงินหรือคืนเงินอัตโนมัติด้วยเหตุนี้

### การตรวจและตัดสินข้อพิพาท

Admin และ Super Admin ดูข้อตกลงเดิม แชท รูปหลักฐาน ธุรกรรม และเหตุผลร้องเรียนตามลำดับเวลา สามารถขอหลักฐานเพิ่มและตัดสินได้สองทาง:

- **คืนเงิน:** ผู้ซื้อได้รับเงินต้นเต็มจำนวน ไม่มีค่าบริการแพลตฟอร์ม
- **จ่ายตามดีล:** ผู้ขายได้รับ 95% แพลตฟอร์มได้รับ 5%

ทุกคำตัดสินต้องมีเหตุผลและยืนยันผ่าน Wallet ตัดสินซ้ำหลังจ่ายหรือคืนเงินเสร็จแล้วไม่ได้ และผู้ดูแลไม่มีคำสั่งถอนเงินพักทั้งหมดเข้าบัญชีตนเอง

### หลักฐานและมาตรการป้องกันโกง

- ข้อความส่งแล้วแก้หรือลบไม่ได้ การแก้ข้อมูลให้ส่งข้อความใหม่
- หลักฐานเพิ่มได้ แต่ห้ามเขียนทับไฟล์เดิม
- รับ JPEG, PNG และ WebP ขนาดไม่เกิน 10 MB ต่อภาพ ตรวจชนิดไฟล์จริงและจำกัดอัตราการอัปโหลด
- เก็บผู้ส่ง เวลา ออเดอร์ และ Hash ของไฟล์กับชุดหลักฐาน
- สร้างรหัสออเดอร์สำหรับใช้ประกอบภาพหรือข้อความนัดหมาย
- แยกรูปประกาศสาธารณะออกจากหลักฐานส่วนตัว
- ให้เฉพาะคู่ค้าและผู้ดูแลที่มีสิทธิ์ดูหลักฐาน และบันทึกการเข้าถึงของผู้ดูแล
- แสดงข้อความจากระบบต่างจากข้อความผู้ใช้ ป้องกันการปลอมข้อความ “เงินเข้าแล้ว”
- ป้องกันซื้อสินค้าตัวเอง ฝากซ้ำ และฝากเงินพร้อมกันสำหรับประกาศเดียวกัน

Hash ใช้ตรวจการเปลี่ยนแปลงข้อมูล ไม่ได้ยืนยันว่าภาพเป็นของจริง และระบบยังตรวจไม่ได้ว่าผู้ขายนำไอเทมเดียวกันไปประกาศซ้ำด้วยข้อมูลใหม่หรือขายนอกเว็บไซต์

### การจัดเก็บข้อมูล

**บนบล็อกเชน:** รหัสออเดอร์ Wallet คู่ค้า ยอดเงิน สถานะ กำหนดเวลา Hash ข้อตกลง/หลักฐาน/คำตัดสิน และสิทธิ์ผู้ดูแล

**นอกบล็อกเชน:** โปรไฟล์ ข้อมูลเกม ประกาศ แชท รูป นัดหมาย รายละเอียดข้อพิพาท รีวิว การแจ้งเตือน และประวัติการทำงานผู้ดูแล

ไม่เก็บรูป แชท ชื่อจริง หรือข้อมูลติดต่อบนบล็อกเชน

กลุ่มข้อมูลหลัก:

- ตลาดและผู้ใช้: `users`, `games`, `listings`, `reviews`
- การซื้อขาย: `conversations`, `messages`, `offers`, `orders`
- การตรวจสอบ: `evidence`, `disputes`, `audit_logs`
- การจัดการระบบ: `notifications`, `staff_memberships`, `role_change_requests`

ข้อมูลสิทธิ์ผู้ดูแลต้องแยกจากโปรไฟล์ที่ผู้ใช้แก้เองได้ และเก็บสถานะเปลี่ยนสิทธิ์ที่ยังรอยืนยันด้วย

### อินเทอร์เฟซหลักของ Contract

ใช้ Contract เดียวแยกบัญชีหลายออเดอร์ ไม่มีระบบอัปเกรด Contract ในเวอร์ชันแรก

| ฟังก์ชัน | หน้าที่ |
|---|---|
| `fundOrder` | ฝากเงินตามข้อเสนอที่ผู้ขายลงนาม |
| `confirmDelivery` | ผู้ขายยืนยันส่งพร้อมใบรับหลักฐาน |
| `confirmReceipt` | ผู้ซื้อยืนยันรับพร้อมใบรับหลักฐานและจ่ายเงิน |
| `openDispute` | คู่ค้าเปิดข้อพิพาทก่อนออเดอร์สิ้นสุด |
| `escalateExpiredOrder` | เปลี่ยนออเดอร์เกินกำหนดเป็นรอตรวจ |
| `resolveDispute` | ผู้ดูแลคืนเต็มจำนวนหรือจ่ายตามดีล |
| `withdrawPendingPayout` | รับเงินที่โอนไม่สำเร็จในครั้งแรก |
| ชุดคำสั่งจัดการบทบาท | แต่งตั้ง ยอมรับตำแหน่ง เปลี่ยน และถอนสิทธิ์ผู้ดูแล |
| ชุดคำสั่งหยุดฉุกเฉิน | Super Admin หยุดหรือเปิดรับเงินฝากใหม่ |

ข้อเสนอใช้ลายเซ็น **EIP-712** ผูกกับคู่ค้า ราคา รหัสประกาศ รหัสออเดอร์ กำหนดเวลา Hash ข้อตกลง เครือข่าย และ Contract ป้องกันเปลี่ยนเงื่อนไขหรือใช้ลายเซ็นซ้ำผิดบริบท

ใบรับหลักฐานเป็นข้อมูลที่ระบบหลังบ้านลงนามหลังเก็บไฟล์แล้ว ผูกกับออเดอร์ ผู้ส่ง ประเภทการยืนยัน และ Hash โดย Contract ตรวจใบรับด้วย ป้องกันการข้ามเงื่อนไขแนบรูปผ่านการเรียก Contract โดยตรง

ใบรับยืนยันเพียงว่าระบบเก็บไฟล์ไว้ ไม่ได้ยืนยันความจริงของภาพ

### การคุมเงินและสิทธิ์

- ค่าบริการคงที่ 500 basis points หรือ 5% คำนวณจำนวนเต็มหน่วย wei
- ตรวจผู้เรียก สถานะ และกำหนดเวลาทุกครั้ง
- ป้องกันการเรียกซ้ำระหว่างโอนเงิน และปรับบัญชีก่อนส่ง ETH
- การโอนให้ผู้รับรายใดล้มเหลว ให้เก็บยอดค้างรับของรายนั้น โดยไม่จ่ายซ้ำหรือทำให้ผู้รับรายอื่นติดขัด
- การหยุดฉุกเฉินหยุดเฉพาะเงินฝากใหม่ ยังเปิดช่องทางข้อพิพาท การตัดสิน และรับยอดค้าง
- Admin และ Super Admin ตัดสินได้เฉพาะออเดอร์ที่เข้าสู่กระบวนการตรวจ
- Super Admin จัดการบทบาทได้ แต่ถอนเงินนอกกติกาออเดอร์ไม่ได้
- คุ้มครอง Super Admin บัญชีสุดท้ายทั้งในระบบหลังบ้านและ Contract
- Private key ของผู้ซื้อ ผู้ขาย และผู้ดูแลไม่ถูกส่งให้เว็บไซต์

### การประสานสถานะเว็บไซต์กับบล็อกเชน

ใช้ Contract เป็นข้อมูลหลักเรื่องเงินและสิทธิ์บนบล็อกเชน ฐานข้อมูลเป็นสำเนาสำหรับค้นหาและแสดงผล

งานเบื้องหลังตรวจเหตุการณ์ทุกหนึ่งนาที บันทึกจุดที่อ่านถึง ป้องกันประมวลผลซ้ำ และตรวจย้อนหลังเมื่อบล็อกเปลี่ยน ส่วนหน้าเว็บติดตามธุรกรรมทันทีหลังผู้ใช้ส่ง

แสดงสถานะแยกกันระหว่าง รออนุมัติ / ส่งแล้ว / กำลังยืนยัน / สำเร็จ / ไม่สำเร็จ การมี Transaction Hash อย่างเดียวไม่ถือว่าสำเร็จ

สำหรับการเปลี่ยนสิทธิ์ผู้ดูแล:

- การเพิ่มสิทธิ์เปิดใช้งานเมื่อขั้นตอนในระบบและบนบล็อกเชนสำเร็จครบ
- การถอนสิทธิ์ปิดสิทธิ์เว็บทันที และติดตามธุรกรรมถอนสิทธิ์ Contract ต่อ
- ระหว่างถอนยังไม่ครบ ต้องแจ้งชัดว่าสิทธิ์บน Contract อาจยังมีอยู่
- ธุรกรรมล้มเหลวต้องลองใหม่ได้และมีประวัติ ห้ามแสดงว่าถอนสิทธิ์ครบแล้ว
- ตรวจสิทธิ์ปัจจุบันทุกคำขอ ไม่เชื่อข้อมูลบทบาทเก่าในหน้าจอหรือ session เพียงอย่างเดียว

## 5. ลำดับพัฒนา การทดสอบ และเกณฑ์ส่งมอบ

### ลำดับพัฒนา

1. **ออกแบบหน้าจอและข้อมูล:** ตลาด ห้องซื้อขาย ผู้ซื้อ ผู้ขาย Admin และ Super Admin พร้อมข้อมูลจำลองสามเกม
2. **พัฒนา Contract:** ระบบพักเงิน ข้อพิพาท หลักฐาน ค่าบริการ และสิทธิ์ผู้ดูแล พร้อมทดสอบ
3. **พัฒนาระบบเว็บไซต์:** Wallet login ประกาศ ข้อเสนอ แชท รูป รีวิว และการแจ้งเตือน
4. **พัฒนาระบบผู้ดูแล:** จัดการผู้ใช้ รายงาน ข้อพิพาท เพิ่ม/แก้ไข/ถอดผู้ดูแล และประวัติการทำงาน
5. **เชื่อมระบบครบวงจร:** ติดตามธุรกรรม งานตรวจสถานะ สิทธิ์ฐานข้อมูล และการจัดการข้อผิดพลาด
6. **ติดตั้งและสาธิตบน Sepolia:** เผยแพร่โค้ด Contract ให้ตรวจบน explorer ตั้งค่า Super Admin คนแรก และเตรียมคู่มือ

การขึ้นระบบจริงบน Sepolia และบริการโฮสต์ต้องใช้บัญชีบริการ Wallet และ Sepolia ETH ของโครงการ หากยังไม่ได้ตั้งค่า ให้มีสภาพแวดล้อมทดสอบในเครื่องพร้อมคำแนะนำครบ และไม่แสดงสถานะว่าออนไลน์แล้ว

### กรณีทดสอบหลัก

| กลุ่ม | สิ่งที่ต้องผ่าน |
|---|---|
| ดีลสำเร็จ | ฝาก → ส่ง → รับ → ผู้ขายได้ 95% แพลตฟอร์มได้ 5% |
| คืนเงิน | Admin คืนเงินต้นเต็มจำนวน ไม่มีค่าบริการ |
| จ่ายหลังข้อพิพาท | Admin จ่ายตามดีลได้ครั้งเดียว |
| หมดเวลา | ส่งหรือรับเกินกำหนดต้องรอตรวจ ไม่จ่ายหรือคืนอัตโนมัติ |
| สิทธิ์และลายเซ็น | ปฏิเสธผู้เรียกผิดคน ยอดผิด ลายเซ็นหมดอายุ และข้อมูลที่ถูกแก้ |
| การทำงานพร้อมกัน | ฝากประกาศเดียวกันพร้อมกัน ยืนยันชนกับเปิดข้อพิพาท และ event ซ้ำไม่ทำให้จ่ายซ้ำ |
| เงินค้างรับ | รับยอดค้างได้เฉพาะผู้มีสิทธิ์ และไม่กระทบยอดรายอื่น |
| บัญชีเงิน | ยอดพักและยอดค้างรับมีเงินรองรับ ไม่มีการถอนนอกสิทธิ์ |
| หลักฐาน | ข้ามใบรับหลักฐานไม่ได้ ตรวจไฟล์ไม่ตรง Hash ได้ และบุคคลอื่นเปิดไฟล์ไม่ได้ |
| ความขัดข้อง | Wallet ปฏิเสธ เครือข่ายผิด Gas ไม่พอ RPC ล่ม หรือรีเฟรชหน้า ไม่ทำให้แสดงสำเร็จเท็จ |
| การจัดการผู้ใช้ | ผู้ถูกระงับสร้างดีลใหม่ไม่ได้ แต่ยังรักษาสิทธิ์ในออเดอร์เดิม |
| การจัดการ Admin | Admin ยกระดับตนเองไม่ได้ เพิ่ม/เปลี่ยน/ถอนสิทธิ์แล้วเว็บและ Contract ตรงกัน |
| Super Admin | ต้องยอมรับตำแหน่ง และถอดบัญชีสุดท้ายไม่ได้ แม้เรียก Contract โดยตรง |
| ประวัติระบบ | ปิดบัญชีหรือถอดผู้ดูแลแล้ว แชท หลักฐาน และคำตัดสินยังอยู่ครบ |

### เกณฑ์ส่งมอบ

สาธิตด้วย Wallet แยกตามบทบาทได้ครบ:

- ซื้อขายสำเร็จ
- คืนเงินหลังข้อพิพาท
- จ่ายผู้ขายหลังข้อพิพาท
- อีกฝ่ายเงียบจนเข้าคิวตรวจ
- Super Admin เพิ่ม แก้ไข และถอดสิทธิ์ Admin
- Admin ระงับผู้ใช้ โดยผู้ใช้ยังเข้าถึงออเดอร์ค้างได้

ส่งมอบโค้ดเว็บ Contract โครงสร้างฐานข้อมูล กฎสิทธิ์ ชุดทดสอบ ข้อมูลสาธิต ตัวอย่างการตั้งค่า และคู่มือติดตั้ง/ใช้งาน

### ขอบเขตที่ยังไม่รวม

ยังไม่รองรับเงินจริง การเปลี่ยน Wallet ของบัญชี ตะกร้าหลายร้าน ประมูล ผ่อนจ่าย คืนบางส่วน NFT เหรียญแพลตฟอร์ม หรือการตรวจส่งมอบผ่าน API เกม

เก็บหลักฐานตลอดช่วงสาธิต และใช้การปิดสถานะแทนลบข้อมูลย้อนหลัง หากไม่มีผู้ดูแลตัดสิน เงินข้อพิพาทจะยังพักอยู่ การขยายเป็นบริการเงินจริงต้องเพิ่มการตรวจความปลอดภัย Contract เงื่อนไขเกม การยืนยันส่งมอบ และนโยบายอายุข้อมูลก่อนเปิดใช้งาน
